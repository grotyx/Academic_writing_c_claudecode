# manuwright agent instructions

This paper uses the manuwright manuscript engine. These rules are mandatory for every agent (Claude Code, Codex, Antigravity/Gemini, opencode, Muse).

- Read the rules before work: `manuwright rules` (full workflow) or `manuwright rules <keyword>` (one section).
- Guides: the rules cite guides as `docs/<name>.md` (for example `docs/writing_guide.md`). They are part of the installed engine, not files in this folder, so do not look for them here: read them with `manuwright guide <name>` (several at once: `manuwright guide <name> <name>`; list: `manuwright guide`). Each `manuwright rules` output ends with the guides it cites; read the ones for the current step in full before doing it.
- Analysis environment: run analysis scripts with `manuwright run data/py/<script>.py` (the paper's own uv-managed Python; build it once with `manuwright env`). Never install into or repair the system, Homebrew or pyenv Python; add packages to `data/requirements.txt` and rerun `manuwright env`.
- Plan first: never write a manuscript section without an approved `drafts/draft_plan.md`, and never write analysis code without an approved `data/analysis_plan.md`. Approved means `- [x] 사용자 승인 완료` is checked. The author ticks it, or approves the plan explicitly in chat ("승인", "approve"); then record exactly that with `manuwright approve <plan> --kind analysis|draft --approved-by "<author>" --quote "<their words>"`. Never approve on your own judgement, and never treat a general "go on" as approval of a plan the author has not seen.
- Grounding: cite only `[EVID:id]` entries present in `knowledge/evidence.md`; use only numbers present in `results/*.csv`. Never fabricate references, statistics, approvals or review records.
- Academic writing: before drafting or rewriting a manuscript section, load its style card with `manuwright style card <section>` (title, abstract, introduction, methods, results, discussion, conclusion) and write to it: its moves, rules and phrasebank, the register of its model paragraphs, and the measured style of the author's corpus when one was learned. Imitate the model paragraphs in form only; never reuse their facts, numbers or citations. Fix the academic-prose findings reported after each edit (`manuwright mode strict` blocks such writes). After rewriting existing text for style, run `manuwright style preserve <before> <after>`: every [EVID:id], number, p value and Table/Figure reference must be unchanged.
- Memory across papers: when the author asks you to remember something ("기억해", "앞으로는 X 대신 Y", "공동저자 추가해줘", "remember", "from now on"), save it in the personal library, additions only: a wording rule with `manuwright library term --prefer "X" --avoid "Y"`; one author's details by editing only that person's lines in the library team profile (`manuwright library profile` prints its path) and this paper's `profile/authors.md`, showing the changed lines first and never guessing ORCID or grant numbers; any other lesson with `manuwright library note "..." --topic journal|reviewer|writing|method|other`. "라이브러리 최신으로 받아줘" is `manuwright library sync --pull`, "이 논문 것을 라이브러리에 올려줘" is `--push`. A CONFLICT or "differs" result is the author's decision. Tell the author in one line what you saved where.
- Evidence and revision: give every evidence.md entry a `Claim Strength` (speculative, observed, supported, strong) and keep cited sentences within it (`manuwright claim-strength drafts`); run `manuwright search audit` before submission and never cite a retracted entry. For a revision, do the letter-blind re-review (`manuwright blind-review packet`, then fill verdicts.md phase by phase without reading the response letter until Phase 2B) before recording response_alignment. After the author edits your drafts, `manuwright style edits --git <rev>` proposes rules; show them, and never tick them yourself. When the author asks in chat, run the tool for them: "내 문체 배워줘" / "learn my style" -> `manuwright style learn <folder>` (3+ papers); "내가 고친 거 배워줘" -> `manuwright style edits --git <rev>` (or two files), show the proposals, and after they approve a rule in chat run `manuwright style edits --approve "<rule>" --approved-by "<author>" --quote "<their words>" --apply`; "과장 표현 검사해줘" -> `manuwright claim-strength drafts`; "참고문헌 다시 확인해줘" -> `manuwright search audit`; "블라인드 재검토" -> `manuwright blind-review packet ...`.
- Gates: do not move past a phase without a recorded PASS. Verify with `manuwright verify --project project.json --profile draft|revision|submission` and the standalone checks (`manuwright citations|numbers|gate ...`).
- Hooks enforce plan-first only in Claude Code and Codex. In other agents, run `manuwright verify` before claiming a step is done.
